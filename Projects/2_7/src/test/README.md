# 대한민국 지도 (Java Swing)

map.svg를 읽어서 시/도를 **랜덤 색**으로 채우고, 각 지역 안쪽에 **한글 이름**을 찍는 Swing 앱.
외부 라이브러리 없이 JDK 기본 기능(DOM 파서 + Java2D)만 사용한다.

## 실행

```bash
javac -encoding UTF-8 -d out *.java
java -cp out KoreaMapApp            # 같은 폴더의 map.svg 사용
java -cp out KoreaMapApp 경로/다른.svg
```

map.svg를 jar 안에 넣고 싶으면 리소스 루트(`/map.svg`)에 두면 자동으로 찾는다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `KoreaMapApp.java` | main, 프레임 + 툴바(색 다시 채우기 / 파스텔 / 이름 표시 / 방식 전환) |
| `KoreaMapPanel.java` | 실제 렌더링, 랜덤 색 생성, 라벨 자동 배치 |
| `LabelPlacer.java` | 라벨 자리 계산 (내접 사각형 / 내접원) |
| `SvgMapParser.java` | SVG → Path2D 변환, 한글 이름 매핑 |
| `MapRegion.java` | 지역 하나(도형 + 이름 + 색) |

## 라벨 위치를 정하는 방법

SVG에는 `<text>`가 없어서 좌표를 직접 계산한다. 두 가지 방식을 넣어뒀고
툴바에서 바꿔가며 볼 수 있다. 기본값은 **내접 사각형**.

### 1) 내접 사각형 (기본) — `LabelPlacer.findLabelBox(shape, aspect)`

도형을 흑백 비트맵으로 굽고, 한 행씩 내려오며 "이 칸 위로 채워진 칸이 몇 개 쌓였나"를
세면 막대그래프가 된다. 막대그래프 안의 최대 직사각형은 스택으로 O(n)에 구할 수 있고,
이걸 모든 행에 대해 반복하면 전체 최대 직사각형이 나온다. 전체 O(가로 × 세로).

`aspect`(글씨의 가로/세로 비)를 넘기면 **면적이 최대인 사각형**이 아니라
**그 글씨를 가장 크게 넣을 수 있는 사각형**을 고른다. 채점 식은 `min(w / aspect, h)`.

글씨는 원이 아니라 가로로 긴 사각형이라서 내접원보다 이쪽이 잘 맞고,
사각형 크기에서 **글자 크기까지 같이 계산**된다.

### 2) 내접원 중심 — `LabelPlacer.findLabelPoint(shape)`

거리 변환(chamfer distance transform)으로 경계에서 가장 멀리 떨어진 픽셀을 찾는다.
자리만 나오고 크기 정보는 없어서, 글자 크기는 지역 bbox 폭 기준으로 줄인다.

무게중심(centroid)을 안 쓰는 이유는 두 방식 공통이다. 전라남도는 섬이 많아 무게중심이
바다로 빠지고, 경기도는 가운데가 서울로 뚫려 있어 무게중심이 서울 안에 찍힌다.
두 방식은 결과가 항상 도형 내부다.

### 공통 마무리

- **글자 크기 하한**이 지도 배율을 따라간다(base의 68%). 창을 키우면 광역시 이름도 같이 커진다.
- 라벨은 계산된 자리에 **그대로** 찍는다. 이웃 이름과 겹쳐도 옮기지 않는다.
  이름이 항상 자기 지역 위에 있는 편이 낫기 때문. 겹칠 때 작은 이름이 위로 오도록
  넓은 지역부터 그리고, 글씨에 흰 테두리가 있어서 겹쳐도 읽힌다.
- 툴바의 `계산 영역 보기`를 켜면 계산된 사각형/기준점이 점선으로 보인다.

검증: 17개 지역 전부 사각형이 도형 내부에 들어가고(격자 441점 샘플 100%),
760×900 창 기준 도는 16.4pt, 광역시는 11.1pt.

수동으로 미세 조정하고 싶으면 `KoreaMapPanel.LABEL_NUDGE`에 SVG 좌표 기준 (dx, dy)를
넣으면 된다. 기본값은 비어 있다.

```java
LABEL_NUDGE.put("Seoul", new Point2D.Double(0, -8));
```

## 이름 바꾸기

`SvgMapParser.KOREAN_NAMES` 한 곳에서 관리한다.
(SVG의 `id`가 키. 예: `Jeju` → `제주도`, `Sejong` → `세종시`)
