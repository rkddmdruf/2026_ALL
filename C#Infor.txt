1. 문제 - 둥근 버튼 모서리가 검게 나온다
================================================================

Button을 상속해서 OnPaint에서 GraphicsPath로 둥근 사각형을 그렸는데
모서리 4곳이 검은 사각형으로 남는다.
BackColor = Color.Transparent 를 줘도 안 된다.


[ 원인 ]

WinForms 그리기 순서는 항상 이렇다.

    WM_PAINT 발생
       |
    OnPaintBackground(e)   <- 배경
       |
    OnPaint(e)             <- 내용 (둥근 사각형 그리는 곳)

Control.OnPaintBackground 의 기본 구현은 BackColor 로 전체를 칠한다.
그런데 ButtonBase 생성자가 ControlStyles.Opaque 를 켜놓는다.
"배경은 내가 OnPaint 에서 통째로 다 그린다" 는 선언이라서
기본 배경 칠을 건너뛴다.

그 상태에서 OnPaint 안에 base.OnPaint(e) 를 호출하지 않으면

    OnPaintBackground -> 아무것도 안 칠함 (Opaque 라서)
    OnPaint           -> 둥근 path 안쪽만 칠함

즉 모서리 4개 바깥은 어느 단계에서도 칠해지지 않는다.
초기화 안 된 그래픽 버퍼가 그대로 보이는 것이 그 검은 네모다.


[ Color.Transparent 가 안 먹은 이유 ]

WinForms 의 Transparent 는 진짜 알파 투명이 아니다.
"부모가 그 자리를 대신 그려주는" 가짜 투명이다.

    Control.OnPaintBackground
       |
    BackColor.A < 255 이고 SupportsTransparentBackColor 가 켜져 있으면
       -> PaintTransparentBackground() 호출
       -> 부모에게 "네가 여기 그려줘" 라고 요청

그런데 Opaque 가 켜져 있으면 이 경로를 통째로 건너뛴다.
그래서 아무도 안 그려서 검게 남았다.

Label 은 Transparent 가 잘 되는데 Button 만 안 되는 이유가 이것이다.
Label 은 Opaque 가 꺼져 있고 Button 만 켜져 있다.

2. 해결 방법 3가지
================================================================

----------------------------------------------------------------
방법 1 - 부모 배경색을 찾아서 직접 칠하기
----------------------------------------------------------------

OnPaintBackground 를 오버라이드해서 부모 체인을 거슬러 올라가며
알파가 255 인(진짜 색을 가진) 첫 조상을 찾아 그 색으로 칠한다.

    private Color EffectiveBackColor() {
        for (Control p = Parent; p != null; p = p.Parent)
            if (p.BackColor.A == 255) return p.BackColor;
        return SystemColors.Control;
    }

    protected override void OnPaintBackground(PaintEventArgs pevent) {
        pevent.Graphics.Clear(EffectiveBackColor());
    }

동작 원리

    Clear(색)          ->  전체를 부모 색으로 칠함
    FillPath(color)    ->  그 위에 둥근 모양을 덮어씀
                           모서리엔 부모 색이 남음 = 투명해 보임

** 중요 **
생성자에서 계산하면 안 된다.

    tableLayoutPanel1.Controls.Add(new RoundButton(...), 0, 0);
    //                             ^ 이 시점엔 Parent == null

new 하는 순간엔 아직 Controls.Add 가 안 끝나서 Parent 가 null 이다.
그래서 필드에 저장해두면 항상 SystemColors.Control 이 잡힌다.
메서드로 두고 "그릴 때마다" 호출해야 한다.

한계
    부모 배경이 단색일 때만 통한다.
    부모에 BackgroundImage 나 그라데이션이 있으면 어긋난다.


----------------------------------------------------------------
방법 2 - 부모를 실제로 그리게 하기 (수동)
----------------------------------------------------------------

좌표를 부모 기준으로 옮긴 뒤 부모의 페인트를 대신 호출한다.
부모 배경이 이미지나 그라데이션일 때 쓴다.

    protected override void OnPaintBackground(PaintEventArgs e) {
        if (Parent == null) { base.OnPaintBackground(e); return; }
        var g = e.Graphics;
        var st = g.Save();
        g.TranslateTransform(-Left, -Top);
        using (var pe = new PaintEventArgs(g, Parent.ClientRectangle)) {
            InvokePaintBackground(Parent, pe);
            InvokePaint(Parent, pe);
        }
        g.Restore(st);
    }


----------------------------------------------------------------
방법 3 - Region 으로 잘라내기
----------------------------------------------------------------

    this.Region = new Region(path);

컨트롤 영역 자체를 둥글게 오려내서 모서리 바깥이 아예 없어진다.
확실하지만 안티앨리어싱이 안 먹어서 모서리가 계단처럼 각져 보인다.
Java 의 setShape 와 같은 한계다.


----------------------------------------------------------------
방법 4 (채택) - Opaque 를 끄는 한 줄  ***
----------------------------------------------------------------

    SetStyle(ControlStyles.Opaque, false);
    BackColor = Color.Transparent;

Opaque 만 끄면 나머지는 WinForms 가 알아서 한다.
SupportsTransparentBackColor 는 ButtonBase 가 이미 켜놨고,
PaintTransparentBackground 가 부모 체인을 재귀로 타고 올라간다.

실제 프로젝트 구조에서의 동작

    RoundButton        투명 -> tableLayoutPanel1 에게 그려달라고
    tableLayoutPanel1  투명 -> NoLoginMain 에게
    NoLoginMain        투명 -> mainPanel 에게
    mainPanel          투명 -> panel1 에게
    panel1             OK   -> BackgroundImage 를 그림

각 단계가 좌표를 알아서 보정해주기 때문에
버튼 모서리에는 그 위치의 배경 이미지 픽셀이 정확히 찍힌다.

** 왜 방법 1 이 아니라 방법 4 인가 **
panel1 에 BackgroundImage(Resources.image, Stretch) 가 깔려 있다.
그 아래 mainPanel / NoLoginMain / tableLayoutPanel1 은 전부 Transparent.
방법 1 로 올라가면 panel1.BackColor(손댄 적 없어서 기본 회색)를 집는데
정작 눈에 보이는 건 이미지다.
검은 사각형이 회색 사각형으로 바뀔 뿐 여전히 어긋난다.

참고: Form 은 BackColor = Transparent 가 아예 안 된다(예외 발생).
      그래서 부모를 타고 올라가는 루프는 반드시 어딘가에서 멈춘다.

4. StringFormat 정리
================================================================

DrawString 에 넘긴 RectangleF 는 "글자를 놓을 상자" 다.
StringFormat 은 그 상자 안에서 글자를 어디에 정렬할지 정한다.

    Alignment     = 가로 정렬 (X축)  좌 / 중앙 / 우
    LineAlignment = 세로 정렬 (Y축)  상 / 중앙 / 하

이름이 헷갈리는데 LineAlignment 가 "줄(line)을 어디 놓을까" 라서 세로다.

값은 StringAlignment 열거형 3개뿐

    Near   = 시작쪽 (가로면 왼쪽, 세로면 위)
    Center = 가운데
    Far    = 끝쪽   (가로면 오른쪽, 세로면 아래)

기본값은 Near / Near 라서 안 넘기면 글자가 왼쪽 위 구석에 붙는다.

    sf 없을 때              sf 있을 때
    +--------------+       +--------------+
    |로그인        |       |              |
    |              |       |    로그인    |
    |              |       |              |
    +--------------+       +--------------+

Near / Far 가 "왼쪽/오른쪽" 이 아니라 "시작/끝" 인 이유는
RightToLeft 가 켜진 아랍어 환경에서 자동으로 뒤집히기 때문이다.

Java 의 Graphics2D 에는 이런 게 없어서
FontMetrics 로 stringWidth() 재고 (폭 - 글자폭) / 2 를 직접 계산해야 한다.
C# 은 그걸 StringFormat 이 대신 해준다.


[ 주의 ]
StringFormat 은 IDisposable 이다. GDI+ 네이티브 자원을 잡고 있다.
OnPaint 는 다시 그려질 때마다(마우스 올릴 때, 창 크기 바꿀 때,
다른 창에 가렸다 나올 때) 호출되므로 매번 새로 만들면 낭비다.

보통 필드로 하나만 만들어 재사용한다.

    private static readonly StringFormat CenterFormat = new StringFormat {
        Alignment = StringAlignment.Center,
        LineAlignment = StringAlignment.Center
    };

5. 객체 초기화자 (object initializer) 문법
================================================================

    new StringFormat { Alignment = ..., LineAlignment = ... }

C# 3.0 부터 있는 문법. 아래와 완전히 똑같다.

    var sf = new StringFormat();
    sf.Alignment = StringAlignment.Center;
    sf.LineAlignment = StringAlignment.Center;

동작 순서
    (1) 생성자 호출
    (2) 중괄호 안의 프로퍼티들을 순서대로 대입

생성자에 인자가 필요하면 같이 쓸 수 있다.

    new StringFormat(StringFormatFlags.NoWrap) { Alignment = StringAlignment.Center }
    //              ^ 생성자 인자              ^ 그 다음 프로퍼티 대입

규칙
    - 인자 없으면 () 생략 가능. 써도 같다.
    - 중괄호 안엔 그 타입의 public 프로퍼티/필드만 가능.
      메서드 호출이나 지역변수 선언은 못 넣는다.
    - 각 항목은 ; 이 아니라 , 로 구분한다.
    - 마지막 항목 뒤에 , 를 남겨둬도 문법 오류가 아니다.

Form1.cs 에서 이미 쓰고 있는 문법이다.

    mainPanel.Controls.Add(new NoLoginMain() {
        BackColor = Color.Transparent,      // <- 이것도 객체 초기화자
    });

var 는 타입 추론. 우변이 new StringFormat 이니 컴파일러가
sf 의 타입을 StringFormat 으로 확정한다. Java 10 의 var 와 같다.

6. 이미지 위 / 글씨 아래 가운데 배치
================================================================

[ 목표 ]
    +------------------+
    |                  |  <- 남는 여백 (startY)
    |      +----+      |
    |      |IMG |      |  imgSize
    |      +----+      |
    |                  |  gap
    |      로그인      |  textSize.Height
    |                  |  <- 남는 여백 (자동으로 같아짐)
    +------------------+

[ 계산 ]

    SizeF textSize = g.MeasureString(Text, Font);    // (1) 글씨 크기 재기
    float totalH = imgSize + gap + textSize.Height;  // (2) 덩어리 전체 높이
    float startY = (Height - totalH) / 2f;           // (3) 위 여백

(Height - totalH) 가 위아래 여백의 합이고
그걸 2로 나누면 위쪽 여백이다.
여기서부터 아래로 쌓으면 자연스럽게 세로 가운데 정렬이 된다.

[ 그리기 ]

    // 이미지 : 가로 가운데는 직접 계산
    g.DrawImage(Image, (Width - imgSize) / 2f, startY, imgSize, imgSize);
    //                 ^ 가로 가운데          ^ 시작 y  ^ 내가 정한 크기로 늘림

    // 글씨 : 폭 전체를 주고 StringFormat 에게 맡김
    var sf = new StringFormat { Alignment = StringAlignment.Center };
    g.DrawString(Text, Font, Brushes.White,
                 new RectangleF(0, startY + imgSize + gap, Width, textSize.Height), sf);
    //                             ^ 이미지 아래 + 간격

글씨 쪽은 LineAlignment 를 뺐다.
사각형 높이를 글씨 높이에 딱 맞췄으니 세로 정렬할 게 없다.

[ 화질 ]
DrawImage 에 크기를 넘기면 원본 해상도와 상관없이 그 크기로 늘려 그린다.
그래서 아래 두 줄을 같이 넣어야 한다. 없으면 축소할 때 계단처럼 거칠어진다.

    g.InterpolationMode = InterpolationMode.HighQualityBicubic;
    g.PixelOffsetMode = PixelOffsetMode.HighQuality;

[ 크기 조절 ]
필드로 빼두면 버튼마다 다르게 줄 수 있다.

    internal int imgSize = 48;   // 이미지 한 변 크기
    internal int gap = 6;        // 이미지와 글씨 사이 간격

객체 초기화자로 바로 지정

    tableLayoutPanel1.Controls.Add(
        new RoundButton(Properties.Resources.login, "로그인", sp.colors[sp.Login]) {
            imgSize = 64,
            gap = 10
        }, 0, 0);

[ 주의 ]
- 이미지가 정사각형이 아니면 가로세로가 imgSize 로 강제돼서 찌그러진다.
  비율을 지키려면 imgSize 를 높이 기준으로 잡고
  폭은 imgSize * Image.Width / Image.Height 로 계산한다.
- MeasureString 은 GDI+ 기준이라 실제 DrawString 결과보다
  좌우로 약간 여유를 더 잡는다. 세로 높이만 쓰면 문제없다.
- 버튼이 세로로 너무 납작하면 startY 가 음수가 돼서 이미지가 위로 잘린다.
  imgSize + gap + 글씨높이 보다는 버튼이 커야 한다.

7. 최종 코드 (RoundButton.cs)
================================================================

using System;
using System.Collections.Generic;
using System.Drawing;
using System.Drawing.Drawing2D;
using System.Linq;
using System.Text;
using System.Threading.Tasks;
using System.Windows.Forms;

namespace _1_6 {
    internal class RoundButton : Button {
        Color color = Color.White;
        internal int arc = 20;
        internal int imgSize = 48;   // 이미지 한 변 크기
        internal int gap = 6;        // 이미지와 글씨 사이 간격

        public RoundButton(Image img, String text, Color color) {
            this.color = color;
            SetStyle(ControlStyles.Opaque, false);

            BackColor = Color.Transparent;
            FlatStyle = FlatStyle.Flat;
            FlatAppearance.BorderSize = 0;

            FlatAppearance.MouseOverBackColor = Color.Transparent;
            FlatAppearance.MouseDownBackColor = Color.Transparent;

            Dock = DockStyle.Fill;
            Image = img;
            Text = text;
            Font = sp.f(12);
        }

        protected override void OnPaint(PaintEventArgs e) {
            if(DesignMode) {
                base.OnPaint(e);
                return;
            }
            Graphics g = e.Graphics;
            g.SmoothingMode = SmoothingMode.AntiAlias;
            g.InterpolationMode = InterpolationMode.HighQualityBicubic;
            g.PixelOffsetMode = PixelOffsetMode.HighQuality;
            using(Brush brush = new SolidBrush(color)) {
                RoundRectagle(g, brush, 0, 0, Width, Height, arc);
            }

            // 글씨 높이를 재서 [이미지 + 간격 + 글씨] 덩어리의 전체 높이를 구한다
            SizeF textSize = g.MeasureString(Text, Font);
            float totalH = imgSize + gap + textSize.Height;
            float startY = (Height - totalH) / 2f;      // 덩어리를 세로 가운데로

            if(Image != null) {
                g.DrawImage(Image, (Width - imgSize) / 2f, startY, imgSize, imgSize);
            }

            var sf = new StringFormat { Alignment = StringAlignment.Center };
            g.DrawString(Text, Font, Brushes.White,
                         new RectangleF(0, startY + imgSize + gap, Width, textSize.Height), sf);
        }

        private void RoundRectagle(Graphics g, Brush brush, int x, int y, int w, int h, int r) {
            GraphicsPath path = new GraphicsPath();
            path.AddArc(x, y, r, r, 180, 90);
            path.AddArc(x + w - r, y, r, r, 270, 90);
            path.AddArc(x + w - r, y + h - r, r, r, 0, 90);
            path.AddArc(x, y + h - r, r, r, 90, 90);
            path.CloseFigure();
            g.FillPath(brush, path);
            path.Dispose();
        }
    }
}


================================================================
8. 남은 개선 거리
================================================================

- RoundRectagle(g, brush, 0, 0, Width, Height, arc)
  오른쪽 / 아래 1px 이 잘린다. Width - 1, Height - 1 이 맞다.

- GraphicsPath 를 using 으로 감싸면 예외가 나도 확실히 해제된다.

- StringFormat 을 static readonly 필드로 빼서 재사용.

- 이미지 비율 유지 (위 6번 주의 참고).

- sp.cs 의 메서드는 소문자 f 다. sp.F 로 쓰면 CS0117 컴파일 에러.
